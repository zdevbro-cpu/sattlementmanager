# 매장 임대차 관리 모듈 개발계획

> Settlement Manager 신규 모듈 (Store Lease Management)
> 작성 기준: 기존 개발계획서 v1 (계약/매출/정산/지급/회계/통계) 위에 추가되는 독립 모듈

---

## 1. 배경 및 목적

### 1.1 배경

- 전시 판매 매장을 급속히 확대 중
  - **라스브러리 (LASBRARY)** — 대형매장, 상가 단독 또는 대형 상업시설 입점
  - **라스온 (LAS-On)** — 소형매장, 병원·카페·마트 등 숍인숍 형태 입점
- 매장 수 증가에 따라 **부동산 상가 임대차 계약** 건수가 급증
- 계약서, 임대인 정보, 보증금·월세·관리비 등이 개인 파일/엑셀로 분산 관리되어 있어
  - 만기·갱신 통보 기한 누락 위험
  - 월 고정비 총액 파악 불가
  - 회계부서의 자료 요청 시 수작업 취합
- 회계관리 부서에서 **다양한 형태의 보고서**를 상시 요구

### 1.2 목적

1. 매장별 임대차 계약을 **단일 원장**으로 관리 (계약서 원본 + 조건 데이터화)
2. 보증금·월세·관리비 등 **고정비 발생/납부를 예측 가능**하게 관리
3. 계약 만기·갱신·인상 시점을 **자동 알림**으로 통제
4. 회계부서의 다양한 보고서 요구를 **파라미터 기반 리포트**로 대응
5. 본 모듈만 사용하는 담당자를 위한 **모듈 단위 접근 제한** 제공

## 2. 개발 범위 (Scope)

### 2.1 포함 ✅

| 구분 | 내용 |
|---|---|
| 임대차 계약서 관리 | 계약 등록/변경/갱신/해지, 원본 파일 첨부, 변경 이력 |
| 임대인 정보 관리 | 개인/법인, 사업자정보, 입금계좌, 연락처, 대리인 |
| 계약 조건 관리 | 보증금, 월세, 관리비, 부가세, 납부일, 인상 조건, 특약 |
| 비용 스케줄 | 월별 발생 예정액 자동 생성, 실제 납부 대사 |
| 만기/갱신 관리 | 만기 D-day, 갱신 통보 기한, 자동 알림 |
| 회계 리포트 | 고정비 명세, 보증금 잔액, 만기 현황, 브랜드/지역별 집계 (Excel 산출) |
| 모듈 전용 접근 | 본 모듈만 접근 가능한 전용 역할 및 라우팅 제한 |

### 2.2 제외 ❌ (본 모듈 범위 밖)

- **매장 등록/마스터 관리** — 기존 `Store` 엔티티 그대로 사용, 신규 개발 없음
- 매장 인테리어·집기·시설물 관리
- 매장 매출/정산 로직 — 기존 ③ 매출관리 / ④ 정산센터 유지
- 임대인 대상 전자계약 발송 (1단계 제외, 향후 검토)
- **회계 모듈 연동 (전표·출금 자동 생성)** — 미사용 예상으로 범위 제외
- 리스회계(K-IFRS 1116) 사용권자산·리스부채 자동 분개 → **4장 4.5 참고, 옵션 처리**

> ⚠️ 범위 밖 항목은 이번 모듈 개발 시 코드를 건드리지 않습니다. 기존 `Store`는 **읽기 전용**으로만 참조하며, `Payment`·`Voucher` 등 회계 관련 테이블은 **일절 접근하지 않습니다.**
> 회계 자료는 시스템 연동이 아닌 **리포트 Excel 산출물**로 회계부서에 전달하는 방식입니다.

## 3. 메뉴 구조 (신규 대메뉴 추가)

기존 8개 대메뉴에 **⑨ 매장임대관리**를 추가합니다.
(② 계약관리 하위로 넣지 않는 이유는 4.1 참고)

```
⑨ 매장임대관리
   ├─ 임대차계약 등록
   ├─ 임대차계약 조회
   ├─ 계약 변경/갱신
   ├─ 계약 이력
   ├─ 임대인 관리
   ├─ 임대료 납부관리
   ├─ 만기/갱신 현황
   └─ 임대차 리포트
```

기존 메뉴 영향:

| 메뉴 | 변경 |
|---|---|
| ① 기준정보 > 거래처관리 | 임대인을 거래처 유형(`LESSOR`)으로 추가 — 코드값 1건 추가 |
| ⑦ 통계 | 임대차 리포트는 ⑨ 하위에 두고, 요약 지표만 ⑦에 노출 |
| ⑧ 시스템관리 > 권한관리 | 신규 권한 코드 추가 (아래 7장) |

## 4. 데이터 설계

### 4.1 설계 원칙 — 기존 Contract와 분리

기존 `Contract`는 **직원/점주/파트너와의 매출·수당 계약**입니다.
임대차 계약은 상대방(임대인), 금액 성격(비용), 라이프사이클(만기·갱신·묵시적 갱신)이 전혀 다릅니다.

→ **`StoreLease`를 별도 엔티티로 신설**합니다.
같은 테이블에 넣으면 정산·수당 계산 로직이 오염되고 조건엔진 규칙이 복잡해집니다.

### 4.2 신규 엔티티

```
Lessor                 임대인 (개인/법인)
StoreLease             임대차 계약 (본 모듈의 중심)
StoreLeaseHistory      계약 변경 이력 (스냅샷)
LeaseChargeItem        계약별 비용 항목 정의 (월세/관리비/기타)
LeaseSchedule          월별 발생 예정 스케줄 (자동 생성)
LeasePayment           실제 납부 내역
LeaseDeposit           보증금 입출 내역 (납입/증감/반환)
LeaseAttachment        첨부파일 (계약서, 등기부, 사업자등록증, 도면, 사진)
LeaseAlert             만기·갱신·인상 알림
```

### 4.3 주요 필드 정의

#### Lessor (임대인)

| 필드 | 설명 |
|---|---|
| lessorType | 개인 / 법인 |
| name | 성명 또는 법인명 |
| bizRegNo | 사업자등록번호 (법인/일반과세자) |
| repName | 대표자명 |
| contact | 연락처, 이메일 |
| bankAccount | 은행 / 계좌번호 / 예금주 |
| taxInvoiceType | 세금계산서 / 계산서 / 미발행 |
| agentInfo | 대리인(부동산·관리단) 정보 |
| memo | 특이사항 |

#### StoreLease (임대차 계약)

| 필드 | 설명 |
|---|---|
| leaseNo | 계약번호 (자동채번, 예: `LS-2026-0001`) |
| storeId | 매장 FK (기존 Store) |
| brand | 라스브러리 / 라스온 |
| leaseType | 신규 / 갱신 / 재계약 / 승계 / 전대 / 해지 |
| lessorId | 임대인 FK |
| propertyAddr | 소재지 주소 (도로명/지번) |
| propertyDetail | 층/호수, 전용면적, 계약면적 |
| contractDate | 계약체결일 |
| startDate / endDate | 임대차 기간 |
| deposit | 보증금 |
| monthlyRent | 월 차임 |
| maintenanceFee | 월 관리비 |
| vatIncluded | 부가세 별도/포함 여부 |
| paymentDay | 납부일 (매월 N일) |
| paymentMethod | 계좌이체 / 자동이체 / CMS |
| rentFreeMonths | 렌트프리 개월수 |
| escalationRule | 인상 조건 (연 N%, 매 N년 재협의 등) |
| renewalNoticeDays | 갱신 통보 기한 (기본 만기 6개월~2개월 전) |
| restorationClause | 원상복구 조건 |
| specialTerms | 특약사항 (텍스트) |
| status | 검토중 / 계약완료 / 진행중 / 만기예정 / 종료 / 해지 |
| createdBy / updatedBy | 감사 필드 |

#### LeaseChargeItem (비용 항목)

계약마다 항목 구성이 다르므로 **가변 항목**으로 설계합니다.

| 필드 | 설명 |
|---|---|
| chargeType | 월세 / 관리비 / 공용전기 / 수도 / 광고분담금 / 주차비 / 기타 |
| amount | 금액 (정액) |
| calcType | 정액 / 실비정산 / 매출연동(%) |
| vatType | 별도 / 포함 / 면세 |
| costCategory | 비용 분류 코드 (리포트 집계·엑셀 산출용) |

#### LeaseSchedule (월별 발생 예정)

계약 등록 시 기간 × 항목으로 **자동 생성**합니다.

| 필드 | 설명 |
|---|---|
| yearMonth | 귀속 연월 (YYYY-MM) |
| dueDate | 납부 예정일 |
| chargeType | 항목 |
| plannedAmount | 예정 금액 |
| status | 예정 / 청구확인 / 납부완료 / 연체 / 보류 |

#### LeasePayment (납부 내역)

| 필드 | 설명 |
|---|---|
| scheduleId | 스케줄 FK (대사용) |
| paidDate | 실제 납부일 |
| paidAmount | 실제 납부액 |
| diffReason | 예정액과 차이 사유 (실비정산 등) |
| taxInvoiceNo | 세금계산서 번호 |
| taxInvoiceDate | 발행일 |
| payerAccount | 출금 계좌 (본사 자금 담당 확인용, 텍스트 기록) |

#### LeaseDeposit (보증금 원장)

보증금은 **비용이 아니라 자산**이므로 별도 원장으로 잔액을 관리합니다.

| 필드 | 설명 |
|---|---|
| txType | 납입 / 증액 / 감액 / 대체 / 반환 |
| txDate | 발생일 |
| amount | 금액 |
| balance | 거래 후 잔액 |
| memo | 사유 |

### 4.4 상태 전이 규칙

```
검토중 ──▶ 계약완료 ──▶ 진행중 ──┬──▶ 만기예정 ──┬──▶ 종료
                                  │                └──▶ 갱신(신규 계약 생성, 이전 계약 종료)
                                  └──▶ 해지 (중도해지)
```

- `진행중` → `만기예정` : 만기 D-180 자동 전환 (배치)
- 갱신 시 **기존 계약을 수정하지 않고 새 계약 레코드 생성** + `prevLeaseId`로 연결
  → 이력 추적 및 과거 조건 조회 보장

### 4.5 리스회계 (옵션 · 1단계 제외)

- 일반기업회계기준 적용 시: **월 임차료를 단순 비용 처리** → 본 설계 기본값
- K-IFRS 1116 적용 필요 시: 사용권자산 / 리스부채 / 감가상각 / 이자비용 분개 필요
- 향후 요구 발생 시 `LeaseAccountingSchedule` 엔티티를 추가하는 방식으로 확장
- **본 모듈은 자동 분개를 수행하지 않습니다.** 필요한 자료는 리포트(6장)로 산출하여 회계부서가 직접 처리

## 5. 화면 설계

### 5.1 화면 목록

| # | 화면 | 유형 | 비고 |
|---|---|---|---|
| L-01 | 임대차계약 목록 | 그리드 + 필터 | 브랜드/지역/상태/만기월 필터 |
| L-02 | 임대차계약 등록/상세 | 탭 폼 | 기본정보 / 비용조건 / 임대인 / 첨부 / 이력 |
| L-03 | 계약 변경·갱신 | 마법사 | 변경 사유 → 조건 수정 → 확인 |
| L-04 | 계약 이력 | 타임라인 | 변경 전/후 diff 표시 |
| L-05 | 임대인 목록/상세 | 그리드 + 폼 | 임대인별 보유 계약 목록 |
| L-06 | 납부 스케줄 | 캘린더 + 리스트 | 월별 납부 예정 |
| L-07 | 납부 등록 | 폼 / 일괄 | 스케줄 선택 후 일괄 납부 처리 |
| L-08 | 만기/갱신 현황 | 대시보드 | D-day 정렬, 신호등 표시 |
| L-09 | 임대차 리포트 | 리포트 뷰어 | 6장 참고 |

### 5.2 L-02 계약 등록 화면 구성

```
[탭1] 기본정보    매장 선택 → 브랜드 자동, 계약유형, 소재지, 면적, 기간
[탭2] 비용조건    보증금, 월세, 관리비, 항목 추가(가변), 부가세, 납부일, 인상조건
[탭3] 임대인      기존 임대인 검색 or 신규 등록, 계좌, 세금계산서 정보
[탭4] 첨부파일    계약서/등기부/사업자등록증/도면/현장사진 (최대 10건, 모바일 촬영 지원)
[탭5] 특약/메모   특약사항, 원상복구 조건, 내부 메모
```

- 저장 시 **LeaseSchedule 자동 생성 미리보기**를 하단에 표시 → 확인 후 확정
- 기존 계약관리 모듈의 첨부/카메라 촬영 컴포넌트 **재사용**

### 5.3 L-08 만기/갱신 현황 대시보드

| 구간 | 표시 |
|---|---|
| D-180 이내 | 🟡 갱신 검토 |
| D-90 이내 | 🟠 갱신 통보 준비 |
| D-60 이내 | 🔴 통보 기한 임박 (상가임대차보호법 갱신요구 기한 고려) |
| 만기 경과 | ⚫ 묵시적 갱신 상태 확인 필요 |

## 6. 회계 리포트 설계

### 6.1 접근 방식

회계부서 요구가 **다양하고 자주 바뀌는** 특성이 있으므로,
매번 화면을 만들지 않도록 **공통 리포트 프레임**을 먼저 구축합니다.

```
[공통 리포트 엔진]
  ├─ 파라미터 영역 (기간 / 브랜드 / 지역 / 매장 / 임대인 / 상태)
  ├─ 집계 축 선택 (행: 매장·브랜드·지역·임대인 / 열: 월·분기·항목)
  ├─ 그리드 (소계·합계·비율 자동)
  └─ Excel 다운로드 (서식 포함)
```

→ 신규 보고서 요구 시 **쿼리 + 파라미터 정의만 추가**하면 되도록 설계

### 6.2 표준 리포트 목록

| # | 리포트 | 용도 |
|---|---|---|
| R-01 | 월별 임차료 지급 예정표 | 자금 계획 |
| R-02 | 월별 임차료 지급 실적표 | 예정 대비 실적 차이 |
| R-03 | 매장별 고정비 명세서 | 월세+관리비+기타, 매장 손익 산정 |
| R-04 | 보증금 잔액 현황표 | 자산 계정 대사 |
| R-05 | 계약 만기 도래 현황 | 갱신 의사결정 |
| R-06 | 브랜드별 / 지역별 임차료 집계 | 경영 보고 |
| R-07 | 세금계산서 수취 현황 | 부가세 신고 대사 |
| R-08 | 미지급 / 연체 현황 | 리스크 관리 |
| R-09 | 임대인별 거래 명세 | 임대인 응대 |
| R-10 | 매출 대비 임차료율 (RTO) | 매장 수익성 판단 — ③ 매출관리 연동 |

> R-10은 기존 매출 데이터를 **읽기 전용**으로 조인합니다. 매출 모듈 코드는 수정하지 않습니다.

### 6.3 회계부서 전달 방식

- 회계 시스템 연동 없이 **Excel 산출물 전달**로 처리합니다.
- 보증금(자산)과 월세·관리비(비용)는 **리포트 상에서 구분 표기**하여 회계부서가 그대로 분개할 수 있게 합니다.
- 리포트 컬럼 구성은 회계부서 현행 엑셀 양식에 맞춰 확정 (10장 5번 항목)

## 7. 권한 설계

### 7.1 기존 역할 매핑

기존 권한 체계(관리자/대표/PM/재무/인사/점주/파트장/파트너/조회전용)에 매핑합니다.

| 권한 | 계약 조회 | 계약 등록/수정 | 납부 처리 | 리포트 | 임대인 관리 |
|---|---|---|---|---|---|
| 관리자 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 대표 | ✅ | — | — | ✅ | ✅ |
| PM | ✅ | ✅ | — | ✅ | ✅ |
| 재무 | ✅ | — | ✅ | ✅ | ✅ |
| 인사 | — | — | — | — | — |
| 점주/파트장 | 본인 매장만 | — | — | — | — |
| 조회전용 | ✅ | — | — | ✅ | — |

신규 권한 코드: `LEASE_VIEW`, `LEASE_EDIT`, `LEASE_PAYMENT`, `LEASE_REPORT`, `LESSOR_MANAGE`

### 7.2 모듈 전용 사용자 (본 모듈만 접근) — **구현 가능**

임대차 업무 담당자에게 **⑨ 매장임대관리 외 다른 메뉴는 아예 보이지도, 접근되지도 않는** 계정을 발급할 수 있습니다.

#### 신규 역할

| 역할 코드 | 명칭 | 보유 권한 |
|---|---|---|
| `LEASE_ONLY_ADMIN` | 임대관리 전용 담당 | `LEASE_VIEW`, `LEASE_EDIT`, `LEASE_PAYMENT`, `LEASE_REPORT`, `LESSOR_MANAGE` |
| `LEASE_ONLY_VIEWER` | 임대관리 전용 조회 | `LEASE_VIEW`, `LEASE_REPORT` |

기존 역할(관리자/PM/재무 등)은 그대로 두고 **역할만 추가**하므로 기존 권한 로직 수정은 없습니다.

#### 4단 차단 구조

권한은 화면에서 숨기는 것만으로는 부족합니다. 아래 4개 지점을 모두 막아야 실제로 제한됩니다.

| 단계 | 위치 | 처리 |
|---|---|---|
| 1. 인증 | Firebase Auth **Custom Claims** | 로그인 토큰에 `role`, `permissions[]` 주입 |
| 2. 메뉴 | 사이드바 렌더링 | 보유 권한 없는 대메뉴는 **렌더링 자체 제외** |
| 3. 라우팅 | React Router `RequirePermission` 가드 | 직접 URL 입력 시 403 또는 `/lease`로 리다이렉트 |
| 4. API | Cloud Functions 미들웨어 | 서버에서 토큰 claims 재검증 — **여기가 실제 방어선** |

> ⚠️ 2·3단계는 UX일 뿐이고, **4단계(서버 검증)가 없으면 API 직접 호출로 뚫립니다.** 반드시 함께 구현합니다.

#### 추가 처리

- **로그인 후 시작 화면 분기**: 전용 계정은 대시보드 대신 `/lease` 로 진입
- **데이터 격리**: 임대차 전용 계정은 매출·정산·급여 테이블에 대한 쿼리 자체를 발생시키지 않음
  (R-10 매출연동 리포트는 이 계정에서 **비노출** 처리)
- **감사 로그**: ⑧ 시스템관리 > 로그관리에 임대차 모듈 접근 이력 기록

#### 개발 부담

기존 권한 체계가 **권한 코드 배열 기반**이라면 역할 2개 + 가드 컴포넌트 1개 추가로 끝나 **0.5일 수준**입니다.
반면 화면마다 역할명을 하드코딩(`if role === '관리자'`)해 둔 상태라면 **권한 코드 기반으로 먼저 리팩터링**이 필요합니다 (10장 7번 확인 항목).

## 10. 우선 확정이 필요한 사항

개발 착수 전 아래 항목의 결정이 필요합니다.

| # | 확인 사항 | 영향 |
|---|---|---|
| 1 | 라스온 숍인숍(병원·카페 등)은 임대차인가, 수수료 매장인가? | 매출연동형 임차료(`calcType=매출연동`) 필요 여부 결정 |
| 2 | 관리비를 실비정산하는 매장이 있는가? | 스케줄 예정액 vs 실제액 차이 처리 로직 |
| 3 | 임차료 납부 주체가 본사 단일인가, 매장별 분산인가? | 전표 생성 단위 |
| 4 | 회계기준: 일반기업회계기준 / K-IFRS 중 무엇인가? | 4.5 리스회계 범위 |
| 5 | 회계부서가 지금 매달 만드는 엑셀 양식 실물 3~5종 | 6.2 표준 리포트 확정 |
| 6 | 기존 `Store` 테이블에 소재지·면적 필드가 있는가? | 중복 저장 여부 결정 |
| 7 | 현재 권한 체크가 **권한 코드 기반**인가, 역할명 하드코딩인가? | 7.2 전용 계정 구현 공수 (0.5일 vs 리팩터링 필요) |

> 특히 **5번(현행 엑셀 양식 실물)** 은 Phase 4 설계 정확도를 좌우합니다. 착수 전 수집을 권장합니다.
